# ReturnGuard AI

> **Protect the retailer. Respect the customer. Explain every decision.**

An explainable, fairness-aware retail returns intelligence platform. It scores return
requests into four classes — `abusive`, `genuine_quality_issue`, `genuine_fit_issue`,
`genuine_wrong_item` — with calibrated probabilities, a cost-aware three-way routing
policy (AUTO-APPROVE / INSPECT / ESCALATE), evidence-backed explanations, fairness
audits, fit-return intelligence, a human review workbench with an audit trail, and a
multilingual customer-resolution assistant (English / Hinglish / हिन्दी).

## ⚠️ Data provenance (read first)

The official competition dataset and `evaluate.py` are **not present in this repository**
(see `PROJECT_STATUS.md`, discovery class C). Everything you see is computed from a
clearly-labeled **synthetic demonstration dataset** (seed 42, ~63,000 returns / 9,000
customers / 150 products with size charts) generated by `scripts/seed-and-train.ts`.
The evaluation contract is a documented **provisional** cost matrix in
`src/lib/ml/evaluator.ts`, implementing the brief's guidance (wrongful suspicion ≈ 10×
missed fraud) and replaceable without touching the UI. No score shown anywhere is invented;
every metric in the UI is computed on held-out test splits at training time.

## Stack

Next.js 16 (App Router) · React 19 · TypeScript strict · Tailwind v4 · PostgreSQL + Drizzle ORM ·
pure-TypeScript ML (TF-IDF + softmax regression + stacking + temperature calibration) · node:test

## Quick start

```bash
cp .env.example .env        # set DATABASE_URL
npm install
npx drizzle-kit push        # create tables
npx tsx scripts/seed-and-train.ts   # generate data, train all models, evaluate, persist (~1-2 min)
npm run dev                 # http://localhost:3000
```

Production:

```bash
npm run build && npm run start
```

Tests:

```bash
npx tsx --test tests/returnguard.test.ts
```

## The three model arms (real training, honest comparison)

| Arm | Implementation | Trained on |
|---|---|---|
| Baselines | approve-all policy, keyword rules | — |
| Structured | multinomial logistic regression over order/behavior features (standardized, one-hot categoricals) | train split |
| Text | word uni/bi-gram + char n-gram TF-IDF (22k vocab, Unicode-aware Hindi/Hinglish tokenizer) + softmax regression | train split |
| **Fused (deployed)** | logistic stacker over calibrated base-model probabilities | **validation split** |

Calibration (temperature scaling) is fitted on validation. All reported metrics —
provisional cost-weighted score, confusion matrix, per-class P/R/F1, macro-F1,
balanced accuracy, Brier, NLL, routing workload — are computed on the untouched
**test** split. Splits are **customer-grouped** (a customer appears in exactly one
split) and a chronology check (months 0–8 vs 9–11) is recorded. See the Model
Evaluation Lab page for the stored numbers from the latest run.

## Routing policy (operational, configurable)

Three-way routing by expected-cost minimization with an uncertainty guard:
`EC(approve) = P(abusive)·fraudLoss`, `EC(inspect) = review labor`,
`EC(escalate) = specialist cost`; cases below 35% top-class confidence always go to
INSPECT. Config in `src/lib/ml/labels.ts` (`ROUTING_CONFIG`) — deliberately separate
from the benchmark cost matrix. Unverified scores can never deny a return; escalation
is a specialist review, not a rejection.

## Fairness

Audited on the test split across three required groupings (new vs established
customers, low-value vs other orders, English vs non-English reasons): routing rates,
wrongful-suspicion FPR, missed-abuse FNR, precision/recall, realized cost, Wilson 95%
CIs, small-sample warnings. Hinglish/Devanagari input is legitimate by design.

## Judge walkthrough (recommended order)

1. **Command Center** — live aggregates, note the demo-data labeling.
2. **Decision Engine → Judge scenario library** — run scenarios 1 (genuine fit),
   2 (possible abuse), 8 (Hinglish) and 10 (conflicting signals); inspect evidence panels.
3. **Explainability Studio** — global learned signals vs per-case contributions.
4. **Model Evaluation Lab** — baseline-vs-model cost comparison, confusion matrix, calibration, chronology check.
5. **Fairness Observatory** — three groupings with error-rate parity and CIs.
6. **Fit Intelligence Studio** — top-5 fit products by volume and rate with corrections.
7. **Human Review Workbench** — open an ESCALATE case, override with a recorded reason.
8. **Audit & System Health** — confirm the override is in the immutable trail.
9. **Resolution Assistant** — draft a Hinglish resolution, approve it as a named human.
10. **Data & Model Management** — ingestion contract, reproducible commands, model registry.

## Remaining limitations

- Returns are used as the eligibility denominator for fit rates (order-level denominators
  are not in the available data) — stated on the Fit page.
- Official evaluation cannot be claimed; provisional matrix is clearly labeled.
- Demo authentication is a free-text reviewer field, not SSO.

## Demo mode vs Real mode

Top-right switch: **Demo data** = the labeled synthetic showcase dataset (judges see metrics, fairness, fit analytics).
**Your data** = cases you score manually or upload as CSV — dashboards, queue and aggregates switch to your real cases only.
The upload contract and 5-row sample live in the Engine page.

## AI integration (Gemini, free)

1. Get a free key: aistudio.google.com → Get API key → Create API key (no billing).
2. Add to `.env`: `GEMINI_API_KEY=your_key` (optionally `GEMINI_MODEL`).
3. Restart. The Resolution Assistant (and AI narrative endpoints) switch from the policy-safe
   built-in writer to Gemini automatically — the UI chip shows which provider is active.
Keys stay server-side; customer text is prompt-injection-hardened as untrusted data.

## Security posture

Security headers + CSP (self-only, Gemini allowlisted), per-IP rate limits on scoring/AI/upload
routes, strict input validation with rejection reasons, SQL via parameterized Drizzle queries,
React-escaped rendering (no dangerouslySetInnerHTML anywhere), no secrets in client bundles
(only NEXT_PUBLIC_* would ever ship). Bucket: predict 60/min, batch 10/min, ai 20/min per IP.

## AI narrative
`POST /api/ai { task: "explain" }` returns a plain-language case explanation for judges/customers.
