## 3. Data availability classification

**Category C — No official data found.**

Consequences, honored throughout the build:

* The official evaluator adapter is implemented as a **replaceable interface**
  (`src/lib/ml/evaluator.ts`) with a documented provisional cost matrix. The provisional
  matrix encodes the brief's guidance ("wrongful suspicion ≈ 10× missed fraud") and is
  clearly labeled PROVISIONAL everywhere it appears.
* A clearly separated **synthetic demonstration dataset** (~63,000 return requests, 9,000
  customers, 150 products) is generated by `scripts/seed-and-train.ts` with a fixed seed (42).
  It is labeled "synthetic demo data" in the UI and in all exported metrics.
* All ML metrics (cost-weighted score, macro-F1, calibration, fairness) are **actually
  computed** on the synthetic validation/test splits by the training script and stored in
  `artifacts/model.json` + the `model_runs` table. No invented scores anywhere.
* The data-ingestion interface (`POST /api/batch`, CSV) accepts real data in the documented
  schema whenever it becomes available, without code changes.
